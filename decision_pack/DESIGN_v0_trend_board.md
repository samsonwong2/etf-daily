# Design: decision_pack v0 持仓趋势展示板（0→1）

Generated by /office-hours on 2026-06-07  
Branch: master  
Status: DRAFT  
Mode: Builder（个人实盘 research）  
Supersedes: v2 自动 `ma_then_cap` 为 **后续 P6+**；v0 仅展示、人工平仓

## Problem Statement

T 日收盘后，需要一张**逐标的趋势体检表**，列出实际持仓的 MA5/MA10/MA20、波动率分位数及少量衍生指标，由操作者**自行判断是否平仓**。v0 **不生成**自动 SELL 规则、不替代 Playbook 判断。

## What Makes This Cool

同一页表格里，把「破线没破线、动量方向、单标的回撤、均线多头还是空头」压缩成可读列，不用在 broker 和 Excel 之间来回切。

## Constraints

- T 日收盘计算，T+1 人工执行（与现有 decision_pack 一致）
- 行情：qlib 收盘价，因果（与 `market.py` 一致）
- 实盘 CSV：`code,name,shares,price`（price=成本）
- v0 **不修改** Tier 阶梯逻辑；Tier 报告仍可并存，但 **orders 不自动生成**

## Premises

1. v0 目标是 **可读性 > 规则完备性**  
2. 所有展示列可复算、可写入 CSV，便于日后回放  
3. 自动 `ma_then_cap` 延后，待你用手工样本验证列足够后再开  
4. 组合层 `vol_percentile_120d`（基准）保留在 `market_snapshot.json`，**不重复**为每只 ETF 再算一遍 unless 列名区分清楚

## v0 指标列定义

### 你点名的 4 项 + Core+ 衍生（共 12 列）

| 列名 | 含义 | 计算（T 日收盘，因果） |
|------|------|------------------------|
| `code` | 标的 | 持仓 |
| `name` | 名称 | CSV |
| `weight` | 占总资产权重 | `portfolio.py` |
| `close` | 收盘价 | qlib |
| `ma5` | 5 日均线 | close.rolling(5).mean() |
| `ma10` | 10 日均线 | rolling(10) |
| `ma20` | 20 日均线 | rolling(20) |
| `vol_pct_120d` | 实现波动率历史分位 | 同 `market.py::_vol_percentile`，vol_window=20, lookback=120 |
| `dist_ma20_pct` | 距 MA20 百分比 | `(close/ma20 - 1) * 100`；负=在 MA20 下 |
| `ret_5d` | 5 日涨跌幅 | close/close.shift(5)-1 |
| `ret_20d` | 20 日涨跌幅 | close/close.shift(20)-1 |
| `ma_stack` | 均线排列 | `bull`: MA5>MA10>MA20；`bear`: MA5<MA10<MA20；否则 `mixed` |
| `dd_20d_high` | 相对 20 日最高收盘回撤 | close/max(close,20d)-1 |

**排序建议（报告默认）**：`dist_ma20_pct` 升序（最弱趋势置顶），或 `weight` 降序（可 CLI 切换）。

### 暂不进入 v0、config 可预留的列（P6 按需开）

| 列名 | 用途 |
|------|------|
| `ma20_slope_5d` | MA20 是否在拐头 |
| `ret_1d` / `ret_60d` | 更短/更长动量 |
| `bb_pos20` | 布林位置 0~1（trend_gate 研究口径） |
| `rsi_14` | 超买超卖参考 |

## 除 MA 与 vol 分位外，为何推荐 Core+ 这 5 列

| 指标 | 回答的问题 | 没有它时的痛点 |
|------|------------|----------------|
| `dist_ma20_pct` | 破 MA20 多少？刚破还是深破？ | 只有 MA 绝对价，难跨 ETF 比较 |
| `ret_5d` / `ret_20d` | 最近在涨还是在跌？ | MA 滞后，看不出短期加速下跌 |
| `ma_stack` | 短中长期是否一致？ | 单看 close vs MA20 漏掉「反弹至 MA10 仍空头排列」 |
| `dd_20d_high` | 这只 ETF 从近期高点跌了多少？ | 组合 `dd_port` 是整体，看不到单标伤害 |

## 架构（v0 最小 diff）

```
portfolio.py (已有)
    ↓ 权益持仓列表
symbol_trend_board.py   ← 新建
    ↓ 逐标的 qlib close → 算列
render.py
    ↓ DECISION_PACK_REPORT.md §「持仓趋势板」
holdings_trend_board.csv
```

**不改动** v1 `orders.py` 同比例逻辑；v0 CLI 增加 `--mode display` 或 config：

```yaml
orders:
  mode: display_only   # display_only | proportional_legacy | ma_then_cap(未来)
```

`display_only` 时：`orders_T+1.csv` **仅表头 + 说明行**，或输出空文件并在报告写「v0 展示模式，请人工决策」。

## 输出契约

### `holdings_trend_board.csv`

- 一行一只 **equity sleeve** 持仓（`defensive_codes` 可单独一节或排除，默认只列权益 ETF）
- 缺失数据：`ma*` 不足 window → 空；`vol_pct` 不足 lookback → 空

### `DECISION_PACK_REPORT.md` 增节

```markdown
## 持仓趋势板（v0 · 人工决策）

> 以下仅为指标展示，不构成自动卖单。Tier 与组合指标见上文。

| code | name | weight | close | ma5 | ma10 | ma20 | dist_ma20% | ret_5d | ret_20d | ma_stack | vol_pct | dd_20d |
...
```

可选：破 MA20 行 **加粗** 或标记 `⚠`（纯展示）。

## Approaches Considered

### A: Core+ 展示板（**选定**）

- Effort: S  
- 新建 `symbol_trend_board.py`，~150 行 + render 一节  
- 不碰 orders 规则  

### B: 直接上 ma_then_cap 自动卖

- 被用户显式推迟；与 v0「自行判断」冲突  

### C: 仅 4 列

- 用户否决（选 Core+ 而非 minimal4）  

## Recommended Approach

**A — Core+ 展示板，`orders.mode: display_only`**

实现顺序：

1. `symbol_trend_board.py`：`build_trend_board(holdings, as_of, config) -> DataFrame`  
2. 复用 `market.py::_vol_percentile`（提取到 `indicators.py` 或 import 私有函数）  
3. `pack.py` 在 `display_only` 分支写 CSV + 报告  
4. `config/default.yaml` 增加 `orders.mode: display_only`  
5. 用 2026-06-05 live CSV 回放目视验收  

## Success Criteria

1. 对每只实盘权益 ETF，12 列均有值（或明确 NaN 原因）  
2. 同一输入跑两次 CSV 一致  
3. 报告一页内可读完（≤20 行持仓）  
4. **零**自动 SELL 行（除非用户改 config）

## What I noticed about how you think

- 你要的是 **「先看见再决定」**，不是再堆一层 black-box regime；这和之前「regime 准确度不是核心」一致。  
- 你明确列 MA5/10/20 而不是只要 MA20，说明你在看 **多周期一致**，`ma_stack` 正是为此服务。  
- 两次否决全自动 v2.1，说明 **可执行简单性** 比理论完备更重要。
